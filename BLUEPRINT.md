## 1. Project Overview

### Vision

Asistente Toni unifica en un solo sistema todos los sistemas sueltos que hoy usa Antonio Oyarzabal (dueño de Gospa Panadería, San Carlos Centro, Santa Fe) para anotar tareas, pagos y pendientes. Antonio tiene TDAH — el problema no es falta de herramientas, es que están repartidas y ninguna insiste lo suficiente como para que algo no se pierda.

Dos puertas de entrada/salida, una sola base de datos:
- **WhatsApp** (lenguaje natural, texto o audio, sobre el canal personal que Antonio ya usa hoy con el contacto guardado "Antonio").
- **App web** (uso diario desde el navegador del iPhone, sin instalar nada).

El corazón del sistema es el **motor de recordatorios persistentes**: cuando algo vence, el asistente pregunta si se hizo — y si Antonio no contesta, vuelve a insistir. Nunca asume que silencio es "hecho". Solo para cuando él confirma explícitamente, o cuando decide abandonar la tarea a propósito.

### Goals

- Que crear/marcar/consultar una tarea por WhatsApp sea tan rápido como mandar un audio de 3 segundos.
- Que ningún pago o compromiso se pierda por falta de insistencia del sistema.
- Que la app web sirva tanto para mirar el estado (barras de progreso, rachas) como para cargar/editar directamente — es una puerta de entrada más, al mismo nivel que WhatsApp.
- Cero infraestructura nueva innecesaria: reusa Evolution API, el patrón de Caja Gospa (Next.js + Prisma + MariaDB en EasyPanel), y el contacto de WhatsApp que ya recibe mensajes automáticos hoy.
- Nunca mandar un mensaje compuesto por el bot a un tercero sin que Antonio lo vea y confirme primero.

### Success Metrics

- Un recordatorio vencido sin confirmar vuelve a insistir en el siguiente intervalo definido — verificable en `reminders_log` (nunca hay un gap de vencimiento → silencio → nada).
- Las 4 vistas (Hoy/Semana/Mes/Avisos) muestran % cumplido correcto contra lo que hay en `task_occurrences`.
- Un mensaje a un tercero redactado por el asistente nunca sale sin un registro `outbound_messages.status = confirmado` previo al envío.
- La app carga y es usable cómodamente en Safari de iPhone (viewport angosto, sin zoom raro, tap targets grandes).

### Decisiones ya resueltas (no volver a discutir)

Estas decisiones se tomaron durante el diseño y son intencionales — no son "a revisar":

1. **Sin n8n en el camino nuevo.** Antes se consideró meter n8n en el medio; se descartó porque esta es la lógica *core* del producto (estado, escalado, confirmaciones), no una automatización simple, y vive mejor como código versionado en la propia app. El workflow existente de n8n (pedido sugerido diario) **no se toca, sigue como está**.
2. **Instancia de WhatsApp: "Pruebas" (personal), no "Gospa" (negocio).** Se evaluó explícitamente cambiar a la instancia de negocio y se descartó — mezclaría recordatorios personales con la conversación de clientes/proveedores. Chatwoot ya está conectado a "Pruebas" y sigue funcionando en paralelo (ver Sección 9, paso 11).
3. **Base de datos nueva y separada** (`gospa_asistente`), en el mismo server MariaDB (`72.60.156.174:3306`) que ya aloja `base_gospa`. Aislada para no arriesgar datos del negocio, sin infraestructura nueva que pagar.
4. **Auth de la app web: PIN compartido**, no un sistema de usuarios. Antonio es el único usuario.

## 5. API Design

La mayoría de las mutaciones de la app web usan **Server Actions** (`lib/actions/task-actions.ts`), no rutas REST — simplicidad: menos boilerplate, menos superficie. Solo hay 2 rutas HTTP reales, porque son las que necesitan un caller externo:

| Method | Path | Description | Auth |
|--------|------|--------------|------|
| POST | `/api/whatsapp/webhook` | Recibe eventos de Evolution API (instancia Pruebas) | Secreto compartido (query param o header, ver Sección 8) |
| GET | `/api/health` | Healthcheck para EasyPanel | No |

### Detalle: `POST /api/whatsapp/webhook`

**Request** (payload real de Evolution API, evento `messages.upsert`):
```json
{
  "event": "messages.upsert",
  "instance": "Pruebas",
  "data": {
    "key": { "remoteJid": "...", "remoteJidAlt": "...", "fromMe": false },
    "message": { "conversation": "recordame pagar el agua el viernes" }
  }
}
```

**Procesamiento** (ver detalle completo en Sección 9, Paso 8):
1. Validar el secreto compartido.
2. Ignorar eventos `fromMe: true` que no sean confirmaciones esperadas del propio flujo.
3. Resolver el contacto emisor (Antonio vs. tercero) vía `remoteJid`/`remoteJidAlt`.
4. Si es audio → transcribir con Whisper.
5. Clasificar intención con OpenAI (`create_task`, `complete_task`, `update_status`, `send_message`, `query`, `confirm_reminder`, `confirm_outbound`).
6. Ejecutar la acción correspondiente contra la base.
7. Responder por WhatsApp vía Evolution API.

**Response:** `{ "ok": true }` — Evolution API no espera un cuerpo específico, solo 200.

### Server Actions principales (`lib/actions/task-actions.ts`)

| Action | Input | Qué hace |
|--------|-------|----------|
| `createTask` | Campos de Task | Inserta tarea, crea la primera `TaskOccurrence` si es recurrente |
| `updateTaskStatus` | `taskId, newStatus, dependsOnContactId?` | Mueve de columna en el Kanban; si pasa a `depende_de_otro` exige `dependsOnContactId` |
| `deleteTask` | `taskId` | Hard delete — a diferencia de un CRM, acá no hace falta soft-delete (no hay reportes de auditoría sobre tareas borradas) |
| `markOccurrenceDone` | `occurrenceId` | Marca completado, detiene el escalado de recordatorios para ese ciclo |

## 8. Authentication & Authorization

### Auth de la app web

Sin tabla de usuarios. Un único PIN (`APP_PIN_HASH`, hasheado con bcrypt, guardado como env var) comparado en `/login`. Al validar, se firma una cookie httpOnly con HMAC (`SESSION_SECRET`) con expiración larga (30 días) — Antonio no debería tener que loguearse seguido.

`middleware.ts` protege todo bajo `(app)/*`, redirige a `/login` si la cookie no es válida. Rutas públicas: `/login`, `/api/whatsapp/webhook`, `/api/health`.

### Auth del webhook de WhatsApp

No usa la cookie de sesión (el caller es Evolution API, no Antonio). Se valida con un secreto compartido propio: `EVOLUTION_WEBHOOK_SECRET` como query param en la URL configurada dentro de Evolution API (`.../api/whatsapp/webhook?secret=...`). Si no coincide, 401 y no se procesa nada.

### Roles & Permissions

No aplica — un solo usuario, sin roles.

### El verdadero gate de seguridad: mostrar antes de enviar

No es un mecanismo de auth tradicional, pero cumple el mismo rol para las acciones irreversibles:

- Si Antonio dicta el texto exacto a mandar a un tercero → `draftedBy = antonio_dictado` → se manda directo.
- Si le pide al asistente que **redacte** el mensaje → `draftedBy = asistente_redactado` → el bot le manda el borrador a Antonio primero, queda en `borrador_pendiente`, y **no sale a nadie** hasta que Antonio responda algo tipo "dale"/"mandalo"/"confirmo" — recién ahí pasa a `confirmado` y se envía.

Esta regla vive en el system prompt de clasificación de intención (Sección 15) y en `webhook-handlers.ts` — no es negociable, ver Sección 16.

## 16. Reglas No Negociables

1. **Silencio nunca es confirmación.** El motor de recordatorios solo se detiene ante un "listo"/"ya pagué" explícito, o un abandono explícito de la tarea. Es la regla central de todo el proyecto — si se rompe, el sistema deja de cumplir su propósito.
2. **Mostrar antes de enviar.** Ningún mensaje a un tercero redactado por el asistente sale sin que Antonio lo haya visto y confirmado por WhatsApp primero. Ver Sección 8.
3. **Una sola fuente de verdad.** WhatsApp, la app web y el cron escriben todos directo a `gospa_asistente` vía Prisma — nunca se construye una API intermedia entre estas piezas para el mismo proceso.
4. **No tocar infraestructura existente que ya funciona:** el workflow de n8n del pedido sugerido, la integración de Chatwoot en la instancia Pruebas, y `base_gospa` quedan exactamente como están.
5. **Nunca commitear secretos.** `.env` fuera de git, `.env.example` con placeholders únicamente.
6. **Toda fecha/hora se calcula en `America/Argentina/Cordoba`**, especialmente en los cron — un bug de timezone acá significa un recordatorio que llega a la hora equivocada o un reset de recurrencia que corre el día equivocado.
